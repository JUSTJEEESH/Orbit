# Orbit iOS Development Rules

You are building a premium native iOS application called Orbit.

Orbit is an AI-powered second brain and memory operating system.

This app MUST feel:
- native
- premium
- fast
- emotionally calming
- Apple-quality
- highly polished
- tactile
- NOT AI-generated
- NOT generic startup UI

## Core Rules

1. ALWAYS use latest stable Swift + SwiftUI APIs.
2. ALWAYS target latest public iOS SDK.
3. NEVER use UIKit unless absolutely necessary.
4. NEVER use ugly AI-generated design patterns.
5. NEVER use gradients unless explicitly requested.
6. NEVER use neumorphism.
7. NEVER use generic “dashboard cards everywhere” layouts.
8. ALWAYS prioritize readability and spacing.
9. ALWAYS optimize for smooth animations and responsiveness.
10. ALWAYS use SF Pro typography.
11. ALWAYS use native Apple interaction patterns.
12. ALWAYS use modern Swift concurrency.
13. ALWAYS separate business logic cleanly.
14. ALWAYS write production-quality code.
15. ALWAYS modularize features.
16. ALWAYS write scalable architecture.
17. ALWAYS support dark mode properly.
18. ALWAYS use accessibility best practices.
19. ALWAYS prefer composition over inheritance.
20. NEVER hardcode magic values.
21. NEVER create bloated views.
22. NEVER create giant ViewModels.
23. ALWAYS use dependency injection.
24. ALWAYS optimize for launch speed.
25. ALWAYS use SwiftData for local persistence.
26. ALWAYS use async/await.
27. ALWAYS use structured logging.
28. ALWAYS use Result types and proper error handling.
29. ALWAYS comment non-obvious architecture decisions.
30. NEVER sacrifice UX for engineering shortcuts.

## Design Direction

The design aesthetic should closely resemble:
- Apple Journal
- Things 3
- Craft
- ATC app aesthetic
- modern Apple Human Interface Guidelines

Visual characteristics:
- solid colors
- zero gradients
- bold contrast
- clean typography
- large readable spacing
- subtle depth
- premium motion
- minimal chrome
- immersive content
- tactile interactions

## Color Rules

- Use solid color surfaces only.
- Avoid washed-out grays.
- Avoid overusing transparency.
- Accent colors should feel intentional.
- Prioritize legibility above visual flair.

## Motion Rules

- Use spring animations.
- Use subtle haptics.
- Avoid flashy transitions.
- Prioritize calm movement.
- Maintain 60fps performance.

## Architecture Rules

Use:
- SwiftUI
- MVVM
- Clean Architecture
- Feature-first folder organization
- SwiftData
- Modular services
- Protocol-oriented design

## AI Rules

AI should:
- reduce friction
- automate organization
- feel invisible
- never overwhelm the user

AI should NOT:
- dominate the UI
- feel gimmicky
- constantly interrupt

## Output Rules

When implementing features:
1. Explain architecture decisions.
2. Generate complete files.
3. Keep files focused and modular.
4. Avoid placeholder implementations unless requested.
5. Use production-quality naming.
6. Include previews where appropriate.
7. Ensure compile-ready code.

## Priority Order

1. UX quality
2. Performance
3. Maintainability
4. Scalability
5. Cleverness

Never compromise UX quality.
